## 尚需处理的功能问题

### C1 / P1：XML 注释仍能让普通字体进入挂载清单

位置：`module/bin/emoji-slots.sh:37-41`。

预处理只去换行并按 `>` 分段，没有识别或排除 XML 注释。以下是合法 XML；其中注释中的两个 family 不属于系统生效配置：

```xml
<familyset>
<!-- Disabled example families:
<family lang="en"><font>Example.ttf</font></family>
<family lang="und-Zsye"><font>Body.ttf</font></family>
-->
<family lang="en"><font>Body.ttf</font></family>
<family lang="und-Zsye"><font>NotoColorEmoji.ttf</font></family>
</familyset>
```

Python 标准 XML 解析结果只包含 `NotoColorEmoji.ttf`。实际 `emoji-slots.sh list` 却同时输出 `Body.ttf` 与 Noto。

进一步执行原始 post-fs-data 脚本（测试目录覆写路径、用文件复制模拟 mount），结果为：

```text
Body.ttf：STOCK_Body.ttf -> TWEMOJI_FIXTURE
description=✅ Twemoji active (2/2 emoji fonts) ...
```

普通字体会在目标路径存在时被替换，错误目标也被计入成功分母。安装器和 WebUI 共用此解析器，同样会继承误选。

**修复要求：** 正确处理注释和 XML 元素边界，确保只有真实 emoji family 的 font 文本能进入清单；加入“注释示例引用了实际正文文件”的反例。仅继续扩展行正则而不验证注释语义，不能关闭此项。

### C2 / P2：合法 XML 属性排版与嵌套元素仍会漏掉真实槽位

位置：`module/bin/emoji-slots.sh:40-41`。

以下四类独立样本，标准 XML 解析均能识别 Noto，但脚本返回空清单且退出码为 0：

```xml
<family	lang="und-Zsye"><font>NotoColorEmoji.ttf</font></family>
<family lang='und-Zsye'><font>NotoColorEmoji.ttf</font></family>
<family lang = "und-Zsye"><font>NotoColorEmoji.ttf</font></family>
<family lang="und-Zsye"><font>NotoColorEmoji.ttf<axis tag="wght" stylevalue="400"/></font></family>
```

第一行的 `\t` 表示真实 TAB；复现脚本生成的文件使用真实制表符。前三类由固定的 `<family ` 与 `lang="` 匹配造成，第四类由要求字体名紧邻 `</font` 造成。上轮报告提出过嵌套元素处理，本轮仍未覆盖。

只含这类声明的设备会找不到目标；与正常排版声明混合时，会只处理部分目标，却把遗漏排除在自检之外。此处未据此宣称特定 OEM 必定使用这些写法。

**修复要求：** 覆盖合法 XML 的属性空白、引号形式和 font 文本/axis 子元素；解析失败需要有可识别状态，不能与“没有 emoji family”混为一谈。

附带观察：font 文件名独占一行时，`list` 会保留尾部空格。当前 shell 消费方分词、WebUI trim 通常掩盖了它，未单独列为功能缺陷，但清单协议应输出规范化路径。

### C3 / P2：product 链接未映射到 Magisk 的 system/product 树

位置：`module/install.sh:62-65`。

新的槽位清单返回 `/product/fonts/ProductEmoji.ttf`，安装器直接拼接 `$MODPATH$p`，创建的是：

```text
实际：<module>/product/fonts/ProductEmoji.ttf
应为：<module>/system/product/fonts/ProductEmoji.ttf
```

Magisk [官方模块布局约定](https://topjohnwu.github.io/Magisk/guides.html)要求 product 替换放在 `system/product`，模块根 `product` 是管理器生成的指向该目录的链接。安装器不应自行以目录占据这个路径。

本轮用真实 on_install 回调和构建 ZIP 做隔离验证，实际创建了根目录 `product/fonts`，没有创建 `system/product/fonts`。product 夹具使用当前 AOSP 支持的 `fonts-modification` / `new-locale-family` 格式。

**影响边界：** product 槽的自挂载路径本身正确，成功时可以掩盖该安装布局缺陷；因此不能说整个模块或所有 product 设备都会失效。但宣称这些槽有原生 Magic Mount 冗余保障尚不成立，应修复映射并在存在 product emoji 的设备验证。本轮未重做实际 Magic Mount 启动测试。

### C4 / P2：WebUI 丢弃非零退出码，将失败检查显示为全部生效

位置：`module/webroot/index.html:150-155`、`184-193`。

`execOut()` 对包装器对象只提取 stdout，忽略 errno/stderr。新增探针返回：

```js
{ errno: 1, stdout: "...\tOK\n...\tOK\n", stderr: "check failed after partial output" }
```

页面仍显示 `✅ Twemoji active — all 2/2 emoji fonts replaced`。这证明只要失败命令留下合法行，就会走成功分支。若输出是部分结果，不能据此证明清单完整或所有目标均已检查。

**修复要求：** 对提供 errno 的对象先验证命令成功，再接受诊断结果；非零时进入明确的失败/降级状态。原生仅返回字符串的接口另需考虑结果完整性信号，不能假定它提供退出码。

## 工程与文档意见

### C5 / P3：打包门禁没有保护更新 URL 的 tag 契约

位置：`tests/build_package.py:63-66`。

门禁检查 asset basename，但不检查仓库及 `/download/<tag>/` 路径。隔离复制模块后，只把 zipUrl 的 `v17.0.3` tag 改为 `v0.0.0`，仍得到：

```text
GATE PASS: v17.0.3 (59) versionCode=59 files=12
```

当前生产 URL 正确，此项是门禁覆盖缺口，不是已发生的更新中断。项目已把 tag 直链定义为不可破坏契约，建议同步校验该字段；远端 Release 标题、正文、资产还需要独立发布核验，当前脚本不会检查它们。

### C6 / P3：验收状态与 README 兼容表尚未同步

`README.md:100` 和 `README_EN.md:100` 仍写 Magisk 管理器链路待验证，与 project_status 记录的 Twemoji_A16_root 三轮回归不一致。主力 agent 已在 TODO 承认这项，宜在本轮修复收尾时同步双语表格。

测试夹具也有一项覆盖质量问题：原 `tests/fixtures/product/etc/fonts_customization.xml` 使用 familyset 且缺少 customizationType，不是当前 AOSP FontCustomizationParser 接受的完整 product 配置。它能测试文本提取，但不能单独证明真实 product schema 的集成。当前官方实现要求 `fonts-modification` 根及对应 customizationType；本轮新增回调夹具补用了真实格式。

原 shell suite 会物理删除测试目录及文件，和项目的禁止自行删除规则冲突。本轮没有原样执行这些删除动作，而是只在运行副本中改为保留目录、移动“缺槽”文件和清空日志；原断言及生产脚本保持原样。建议将原测试也改为安全保留/独立工作目录。
